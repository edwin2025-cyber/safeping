# SafePing dashboard version 5: everything that changed

This file lists everything done to the staff dashboard in one long work session, in five rounds of requests. Each round lists what was asked, what was built, and where it lives in the code.

The full reference for how the dashboard works today is [dashboard.md](dashboard.md). Screenshots of every screen, light and dark, are in [screenshots/](screenshots/). They were taken at the end of round 4, so they do not show the round 5 battery colors.

## Rules that held the whole time

- No git commands that change the repo. Edwin runs all of them. Only `git status` and `git diff` were used.
- No Claude author, co-author or "generated by" text anywhere.
- No secrets were opened or printed: no `config.py` under `firmware/` or `tests/`, no `server/safeping.db`, no `.env*` file (including `dashboard/.env.mock.local`), no `carto_key.txt`, no `safeping-private`.
- Nothing changed in `firmware/`, `tests/`, `logs/`, `server/safeping.db*`, `server/places.json`, `validate.py`, or any accept or reject decision. `test_attacks.py` still passes 16 of 16.
- Existing `/api/*` fields were kept. Only new fields and routes were added.
- No emojis and no em dashes in the UI or the docs.
- `npm.cmd`, not `npm`, in PowerShell.
- Testing used a made-up demo database and made-up places in a temporary folder, never the real database.

## Round 1: the first version 5 pass

Asked for in `dashboard-v5-prompt.md`.

- **Light theme.** A warm ivory theme. It was undone in round 2 because Edwin preferred pure white.
- **Sidebar.** A wordmark at the top and a fold button (Ctrl+\). Folded, it shows an "S". Overview, Live and Devices sit under Monitor, and Settings under Workspace. Live shows the open count, a red pill when an urgent alert is open. "Server online" and the account row ("Safety office", "Login coming soon") are at the bottom. Under 1280 px wide it folds by itself.
- **Find a student (Ctrl+K).** A search box that finds students by name or Fob ID, plus their recent alerts. A student opens the device panel and an alert opens the alert panel. New server route: `GET /api/search`.
- **Top bar.** Relay, Reference and the clock are quiet 13 px text with fixed widths, so nothing jumps when a value changes.
- **Live and Devices rows.** Calm rows with no colored backgrounds, 48 px tall.
- **Map circles.** A circle shows only for the alert that is hovered or selected. The version 4 fix (markers and circles move together) was kept and checked again.
- **New Overview page.** Four stat tiles (Open now, Urgent open, Last alert, Today), a stacked Alerts chart with a tooltip that glides, a map of where alerts happened, and Recent activity. It all fits on one screen at 1280 x 650. A range picker (Today, Last 7 days, Last 30 days, This month, Custom) and Export.
- **Layout.** Content is capped at 1600 px wide, with rules for laptop, wide and narrow screens.
- **Settings.** It opens as one fixed-size window, so it never resizes between sections. There is a new Health section, with delivery by link, rejected messages, Fobs not seen in 24 h, low battery and the reference sensor. A temporary font picker was added for comparing fonts.
- **Server.** A new `GET /api/alerts/<id>` route, so older alerts open from Overview and search. `/api/stats` gained new fields for Overview: `open_by_type`, `urgent_open`, `last_alert`, `today_count`, `usual_per_day`, `points`, `indoor_count` and `recent_events`. New helpers are in `server/db.py`. Both new routes are behind `require_login`.
- Edwin's answers to the four questions: leave STATUS out, add `GET /api/alerts/<id>`, use a dark icon in dark mode, and keep today's width.

## Round 2: white theme, Busy hours, divider, tags, polish

- **Pure white light theme again.** The version 4 values came back.
- **Busy hours chart.** It sits next to the Alerts chart, two thirds and one third. It shows 24 bars, one per hour of the day, built from `weekday_hour` in `/api/stats`.
- **Smoother Alerts chart.** Smooth S-curves that never overshoot the real counts (Recharts `bumpX`). Each type has a 2 px line, and one soft fade runs under all the bands. Gridlines are faint dashes.
- **Split view divider.** Drag it to give the list or the map more room. The list keeps at least 360 px and the map 320 px. Left and Right keys move it, and a double-click or Enter puts it back in the middle. The browser remembers the position.
- **Colored tags are back.** Types and links are tinted rectangles with the icon and word in a darker shade of the same color.
- **Ctrl+K hint.** It only shows when you point at "Find a student", with a faint rectangle behind the row.
- **Satoshi became the default font.**
- **Row buttons.** Acknowledge and Open have their own column at the right end of the row, so they never cover the time.
- **The sidebar opens and closes smoothly,** over about 0.2 s. Icons stay put and labels fade. It does not animate when the computer asks for reduced motion.
- **Styled dropdowns everywhere.** A quiet button opens a styled list with a check on the current choice. Up, Down, Home, End, Enter, Space, Esc and Tab all work. The code is the `Select` in `Controls.jsx`, on top of `Popover.jsx`.
- **"SO" account circle.** It has its own gray and a thin ring, so it stays visible on hover.

## Round 3: fonts, magenta, alert panel, Excel, smooth chart

- **Satoshi letters with General Sans numbers.** The app font "SafePing Sans" uses Satoshi for letters and General Sans for the digits 0 to 9 (CSS `unicode-range` in `base.css`). All four font rules must share one weight range (200 to 900), or Chrome never uses the digit font.
- **Magenta.** The Open dot and the Mock data tag are magenta instead of orange.
- **Breadcrumbs** ("SafePing / Live") are a little thicker (weight 500).
- **Overview tiles.** The context lines have no commas, just space and an icon per item, and they are semibold.
- **Alert panel in sections:**
  - A header with the name, the type tag, the status and the Fob ID, with Acknowledge and Resolve on the right.
  - Pressed and Place cards.
  - Review cameras.
  - The map.
  - A timeline: Pressed, Text to duty phone, Acknowledged, Resolved.
  - A Fob section.

  The old layout is still in the code (see Undo below).
- **Types with 0 in the chart.** The legend shows each type's count. A type with 0 is faded and has nothing to draw. That is expected, not a missing color.
- **Busy hours shaded by count.** Each bar is a shade of blue from faint to deep. When the busiest hour has 6 alerts or fewer, each count gets its own shade. Hours with no alerts are short gray dashes.
- **Excel export.** Export > Excel workbook builds a `.xlsx` in the browser from the same CSV (exceljs, loaded only on export). It has two sheets:
  - Summary: formulas by type and status, and every day of the range.
  - Alerts: an Excel table with filter buttons, a frozen header, real dates, and colored Type, Status and Battery cells.

  The CSV is unchanged.
- **Rich copy.** Copy details and Copy for security copy a formatted table for Excel, Word and email, plus plain text for texting and Notepad. This works on plain http too.
- **Review cameras card.** A plain card with no yellow tint. The time window is the large line.
- **Smooth chart.** The chart grows up from the baseline in 0.9 s with one long ease-out, every band together. A poll does not replay it.
- **Gliding hover dots.** The dots and guide line glide to the next day in 0.26 s instead of jumping. They only rest on real days or hours. A dot that followed the cursor freely would show made-up values like 5.5 alerts at 12:30.
- **Suspicious color, try 1.** Amber changed to a deep gold. Amber failed the color check next to Medical red.

## Round 4: blue Suspicious, GPS hidden, device panel, empty preview

- **Suspicious is azure blue.** Light #1C8EDB (28,142,219), dark 82,200,242. Gold was not liked, and neither was an ocean blue. A deep true blue fails the color-blind check next to Silent violet, so the blue leans toward cyan. Check results: color-blind separation 9.4 (target 8) and normal-vision separation 16.8 (target 15) in light, and 9.2 and 17.7 in dark. The icon, tag, map marker, chart and Excel all use it.
- **The WiFi tag was slate** instead of teal, and Review cameras had its own teal. Both were changed again in round 6 (below).
- **GPS point hidden.** The Place card keeps Open in Google Maps. "Show GPS point" reveals the coordinates and accuracy, and "Hide GPS point" hides them. They start hidden every time. The cameras card says "Within 62 m of the GPS point" without numbers. The copied text still has the point, because security needs it.
- **Device panel in sections,** like the alert panel:
  - A header with the name, Fob or Reference board, the link tag and the Fob ID.
  - Three cards: Last seen (with the message number), Battery (with a bar and a word), and Open alerts (with "Needs action" or "None open").
  - The alert history with a type filter.

  The reference board shows a Role card instead of battery and history.
- **Last alert tile.** The big line is 38 px tall, so the bottom of the "g" in "2 min ago" is no longer cut off.
- **Empty dashboard preview.** Settings > About > Testing > "Show empty dashboard" shows SafePing on its first day, with no Fobs, alerts or readings, to check that nothing breaks.
  - It affects only that browser tab (session storage) and stops when you exit or close the tab.
  - An orange banner with Exit preview stays up the whole time, and the tab title starts with "(Preview)".
  - The dashboard answers its own data requests with empty results. The server is not touched and no data is deleted. `/api/config` still comes from the server.
  - Real alerts are hidden in that tab, so do not leave one open on the duty laptop.
  - The code is in `dashboard/src/lib/preview.js`.
- **Docs and screenshots.** `dashboard.md` was updated for every change, including a fix to the font table. All 60 screenshots were retaken, with new ones of the empty preview and the device panel.

## Round 5: battery colors

- **Green at 20% and up.** A clear green bar (light 22,163,74, dark 74,222,128). The number stays plain.
- **Yellow under 20%.** A yellow bar (234,179,8) and a bold yellow "Low" word (plain text, no box). The percent is semibold too.
- **Red under 10%.** A red bar and a semibold red "Very low" tag. The percent is semibold too.
- The device panel's Battery card shows the same colors with a bold word under the bar: green "Good", yellow "Low, under 20%" or red "Very low, under 10%".
- This shows in three places: the Devices list, the device panel and the alert panel's Fob section. One `Battery` component and one `BatteryTag` in `DevicesPage.jsx` drive all three.
- The words were boxed tags at first. Edwin preferred plain heavy colored text, so the boxes were removed. Yellow text on white has to be a deep golden yellow (150,96,0) to pass 4.5:1 contrast, darker than the bar.
- The "low batteries" count in the Devices summary and in Settings > Health changed from orange to this yellow.
- The Devices Battery column is a little wider (20%, up from 16%) so "Very low" never wraps. Student and Link gave up the space.
- **Excel.** Battery cells are red under 10, yellow under 20 and green from 20. Empty battery cells now stay plain. Before, Excel counted an empty cell as 0 and colored it red.
- Mock data: Mock Student Charlie's battery went from 31% to 15%, so mock mode shows all three colors.

## Round 7: grays, magenta Suspicious, blue Busy hours, calendar

- **Link tags are three grays,** not green, yellow and gray: Unknown light, LoRa middle, WiFi dark. This replaces the teal and sand tags from round 6.
- **Suspicious is magenta,** the same pink as the Open dot. Everything follows: the tag, icon, map marker and circles, chart, and the Excel and Copy details colors. The color check says it is too close to Medical rose, which Edwin chose anyway (see dashboard.md, Look and colors). The Open dot was the same pink, so it became teal (see below).
- **The Open dot is teal** (light 14,116,144, dark 34,211,238), chosen from four options. The first teal tried was too pale on the selected row, so it was deepened. The Open cells in Excel and Copy details are teal too.
- **Review cameras stays blue,** which is no longer the Suspicious color, so it looks different from it again.
- **Busy hours is the old blue again.**
- **The Mock data tag is gray.**
- **Custom date range is a calendar.** It replaces the two browser date boxes. It opens when Custom is picked: click the first day, then the last, and it applies and closes. Days in the range are shaded and the ends are solid blue. Future days and ranges over 366 days are off. Keys: arrows for day and week, Page Up and Page Down for month, Esc to close. The new file is `dashboard/src/components/DateRangePicker.jsx`.
- Checked with a clean build, the contrast check, and a short browser test of the calendar (opening, picking, keys, no console errors).

## Notes and open choices

- **Busy hours** bars are blue, close to the new Suspicious blue. They do not stand for a type, but they could change to another color if that is confusing.
- **Low battery elsewhere.** The Devices summary ("1 low battery") and Settings > Health > Low battery still use orange. They could switch to the new yellow to match.
- **Empty preview.** It hides real alerts in its tab. Exit it before leaving the laptop.
- **Map offset.** One 14.6 px gap between a marker and its circle was seen once early on and never seen again in any later run.
- **npm audit.** It lists a moderate advisory in `uuid`, which exceljs depends on. The dashboard never reaches that code path.
- **Edwin's mock server.** One was running on port 5173 during this work. It was left alone. Test servers used ports 5174 and 5055 and were stopped.

```
npm.cmd run build         # then python app.py in server/ serves it
npm.cmd run contrast      # color check
```
